# Release Skill — skipstone

Release a new tagged version of the skipstone Go library.

skipstone is a **library** (no binary, no goreleaser, no PGO). The git tag
**is** the version — there's no `VERSION` file. Consumers do
`go get github.com/kfet/skipstone@vX.Y.Z`.

## Pre-flight

1. **Clean working tree** — `git status` must show no uncommitted changes
   (other than what this release will produce).
2. **On main** — `git rev-parse --abbrev-ref HEAD` must be `main`. If not,
   merge first; we don't tag feature branches.
3. **Up to date with origin** — `git fetch && git status` should show
   `Your branch is up to date with 'origin/main'`. If a remote doesn't
   exist yet, skip; the first push happens at step 9.
4. **CI green** — if origin exists, check the latest run on `main`:
   `gh run list --branch main --limit 3`.

## Steps

1. **Full local build & test** — run `make` (default target = test-fast +
   e2e). Must show:
   - `✓ gofmt clean`
   - `✓ go vet clean`
   - `✓ coverage 100%`
   - `ok  github.com/kfet/skipstone/e2e` (cross-check vs aws-sdk-go-v2)
   - `✓ all green`

   If anything fails, **stop**. Releases never go out red.

2. **Check CHANGELOG** — read `CHANGELOG.md`. Confirm entries exist under
   `## [Unreleased]`. If empty, ask the user whether to abort or proceed
   with an empty release section.

3. **Determine version** — if the user provided one, use it. Otherwise
   apply semver rules to the `[Unreleased]` section:

   | CHANGELOG content | Pre-1.0 bump | Post-1.0 bump |
   |---|---|---|
   | `### Removed` or breaking `### Changed` | minor (0.1.0 → 0.2.0) | **major** (1.2.0 → 2.0.0) |
   | `### Added` | minor (0.1.0 → 0.2.0) | minor (1.2.0 → 1.3.0) |
   | only `### Fixed` / non-breaking `### Changed` | patch (0.1.0 → 0.1.1) | patch (1.2.0 → 1.2.1) |

   The current version is the latest `vX.Y.Z` git tag
   (`git describe --tags --abbrev=0` — empty if no tags yet, in which
   case the first release is **v0.1.0**).

   State the chosen version and proceed.

4. **Update CHANGELOG** — rename `## [Unreleased]` to
   `## [X.Y.Z] - YYYY-MM-DD` (today's UTC date), then add a fresh empty
   `## [Unreleased]` section above it with the standard subheadings
   placeholder. Update the link footer at the bottom of the file:

   ```
   [Unreleased]: https://github.com/kfet/skipstone/compare/vX.Y.Z...HEAD
   [X.Y.Z]: https://github.com/kfet/skipstone/releases/tag/vX.Y.Z
   ```

   Keep reverse-chronological order.

5. **Commit** — `git add CHANGELOG.md && git commit -m "release: vX.Y.Z"`.
   Confirm `git status` is clean afterwards.

6. **Tag (annotated)** — annotated tags carry author/date/message and are
   what `pkg.go.dev` displays. **Do not** use lightweight tags.

   ```bash
   git tag -a vX.Y.Z -m "release: vX.Y.Z"
   ```

   Always pass `-m` to avoid opening an editor.

7. **Verify the tag locally** —
   ```bash
   git tag -v vX.Y.Z 2>&1 | head -5   # confirms it exists
   git show vX.Y.Z --stat | head -20  # shows what's in it
   ```

8. **Push commit + tag together** —
   ```bash
   git push origin main --follow-tags
   ```

   `--follow-tags` pushes annotated tags reachable from the pushed
   commits in the same operation. Don't push the tag separately unless
   you've already pushed the commit and forgot the tag.

9. **(First release only) Create the GitHub repo** if it doesn't exist:
   ```bash
   gh repo create kfet/skipstone --public --source=. --remote=origin --push
   git push origin --tags
   ```

10. **Wait for proxy.golang.org** — Go's module proxy fetches the new
    version on first request. Trigger it explicitly so consumers don't
    hit a cold-cache delay:

    ```bash
    curl -fsSL "https://proxy.golang.org/github.com/kfet/skipstone/@v/vX.Y.Z.info" | head -c 200
    ```

    A 200 response with JSON containing `"Version":"vX.Y.Z"` confirms
    the proxy has indexed the release.

11. **Create a GitHub Release** with notes from the CHANGELOG section:

    ```bash
    gh release create vX.Y.Z --title "vX.Y.Z" \
      --notes "$(awk '/^## \['"X.Y.Z"'\]/,/^## \[/{if(/^## \[/ && !/X.Y.Z/)exit; print}' CHANGELOG.md | tail -n +2)"
    ```

    (Or use `gh release create vX.Y.Z --generate-notes` for autogenerated
    PR-based notes if the CHANGELOG entry is sparse.)

12. **Watch CI** — the `test` and `e2e` workflows run on the tag push.
    Poll until they're done:

    ```bash
    gh run list --limit 5 --json status,conclusion,name,headSha,createdAt
    ```

    Match by `headSha` against the release commit (tag-triggered runs
    don't always show under `--branch main`). If anything fails, report
    and stop — the tag is already pushed, but a follow-up patch release
    fixes things faster than rewriting history.

## Important notes

- **Annotated tags only.** `pkg.go.dev` and the Go module proxy treat
  lightweight tags as second-class. Use `git tag -a -m`.
- **Avoid interactive git.** Always pass `-m` to `git commit` and
  `git tag -a`.
- **Never delete a public tag.** Once pushed, `proxy.golang.org` caches
  it forever (immutable by design). If you tagged something broken,
  release a new patch version — don't try to "fix" the bad tag.
- **e2e is mandatory pre-release.** `make e2e` cross-checks SigV4 +
  event-stream framing against `aws-sdk-go-v2`. Skipping it defeats the
  whole reason this project exists.
- **CHANGELOG link footer matters.** Broken `[X.Y.Z]:` links in
  `CHANGELOG.md` are the most common cosmetic regression — they only
  surface when someone clicks a version header on GitHub.
- **Pre-1.0 freedom.** Before v1.0.0 we treat any breaking change as a
  minor bump (per common Go practice and semver §4). After v1.0.0 we
  hold the line: breaking change ⇒ major bump, full stop.

If any step fails, stop and report. Do not retry destructive operations
(tag push, GitHub release) without confirming the user wants to proceed.
